# 語音逐字稿校對 Prompt

你的任務是校對一份由自動轉錄產出的中文逐字稿。
原始錄音是尚承的口語自述(暗流隨筆素材),用途是**留住當下思緒 + 記憶錨點 +
長期知識庫**,不是給人發表的文章。語速、停頓、繞、重複都是素材的一部分,
**不能潤稿**。

**目標是「帶質感的半成品」,不是「語法完美的逐字稿」。** 可以帶錯字,
不需要追求 100%。

## 你可以做的修正

1. **明顯的辨識錯誤**(同音字、近音字誤判):**直接填最合理的 best-guess**。
   不要因為不是 100% 確定就留白 — 低信心時用 `<sup>字？</sup>` 輕度標記。
2. **標點符號**:依語意和自然停頓補逗號、句號、問號。不要用驚嘆號,
   除非語氣明顯激動。
3. **分段**:依話題或思緒的轉換分段,每段不要太長(口語的一個「想法單位」
   就是一段)。段與段之間空一行。
4. **明顯的口誤回頭**:如果說話者說「我覺得這個……啊不是,我想說的是……」,
   保留後面那次,前面那次可以刪掉。但如果不確定是不是口誤,保留全部。
5. **講卡 / 情緒停頓 / 話題跳空檔**:用 `……`(全形三點)帶過。
   大多數「語意斷裂」其實是真實發生的語音事件,不是辨識錯誤。
6. **開頭的日期報時**:錄音開頭報日期如果有講錯重來
   (例:「今天是8月……2026年的8月14號」),直接整理成一次到位的
   「2026年的8月14號」格式,不保留講錯重來的部分。
   日期是檢索錨點,格式統一優先於保留 stutter;這是**唯一**固定允許
   刪掉口誤重來的位置,其他地方仍照第 4 條的保守原則。

## 你不可以做的事

- **不要潤稿**。不要把口語改成書面語,不要替作者「講得更好」,不要合併句子
  讓邏輯更順。口語本來就有重複、繞、停頓,那是素材的一部分。
- **不要刪減語氣詞**。「嗯」「欸」「對」「然後」「就是」「我覺得」這些口頭禪和
  填充詞**全部保留**,它們是節奏和情緒的痕跡。
- **不要重組順序**。即使話跳來跳去,維持原本的時間順序。
- **不要加入任何不在原稿裡的內容**。不要補充說明、不要寫小標、不要加註解
  (包括 `[註：...]` meta-note — 那是**使用者事後手動補**的,Claude 不碰)。
- **不要做摘要或總結**。這一步只做校對。
- **不要過度標記**。滿眼 `[？]` 代表 prompt 沒貫徹。預設是 best-guess 直接填,
  標記是例外,不是常態。

## 標記原則(新版,方向 B)

**預設:不標記,直接 best-guess 填入**。視覺上校對稿應該是一篇順暢的文章,
不應該滿眼都是方括號問號。

只有這三種情況才用標記:

### 🟡 低信心 guess → `<sup>字？</sup>`

當 best-guess 來自單一引擎、或幾個引擎互相矛盾、或你讀起來覺得有點怪,
把不確定的字用 `<sup>字？</sup>` 包起來。例:

> 我那時候也曾跟朋友說要<sup>開看看？</sup>,現在真的是還是要有錢

視覺上幾乎看不到,但要找不確定處還是挑得出來。

### 🔴 嚴重語意分歧 → `[？]` + 文末說明

當不同來源給出**語意完全不同**的版本(例:主力引擎說「想要陪伴」,
第 4 來源說「比較偏」),這會影響整段情緒方向,**使用者必須重聽決定**。
這時在該處用 `[？]`(沒有編號),並在文末加一行簡短說明:

> 她想要[？]陪伴,他自己很內疚

> ---
> *「想要陪伴」處 Get 筆記版聽成「比較偏,做得不夠」,~37:32,建議重聽*

這種標記**極少**,一份稿子通常 0–2 個。寧可沒有,不要濫用。

### 🔴 陌生專有名詞 → `[？]` + 文末說明

明顯是人名/產品/概念,但 `dictionary.yaml` 沒收錄,各引擎又對不上時,
用 `[？]` 標記,並在文末附一行:

> 後來 [？] 跟我說了一件事

> ---
> *[？] 處疑似人名,請補進 dictionary.yaml*

### 🔴 主力全崩 + 單一獨家來源 → `[？]`(最重要的保險絲)

如果三個主力引擎(funasr/apple/sensevoice)在某段**全部辨識崩壞**(亂碼、
語意不通、明顯的意識流胡言),先看 FireRed 第三票 — 它在主力全崩段
常是唯一給出可讀版本的引擎,它的版本可以填(照低信心標記原則)。
如果連 FireRed 也崩,而**只有 Get 筆記有一個清楚的版本** —
**不要直接填入那個版本**。

**原因**:引擎全崩的段落通常是語速快、情緒強、口音重的段落,
恰好是最需要人耳確認的地方。Get 筆記在這種段落雖然偶爾能撈到語意,
但它也可能基於內部 AI 補完而產出「似是而非」的版本 — 文法通順、
語意合理、甚至跟該筆記的「智能總結」互相印證,**但可能完全不是使用者說過的話**。

**這種情況不算「多數決」,而是「唯一可疑證人」**,絕對不能當確定答案。

**做法**:在該處用 `[？]`(可以包含前後的錨點字),並在文末明確註記
「引擎全崩,此處為 Get 筆記獨家版本」:

> 其實也是延伸到父母的、各自的兩句話。[？]

> ---
> *「父母的兩句話」處引擎全崩,Get 筆記獨家版本是「一生一世的義務 / 不是他的責任」,
>  單一來源可靠度低,必須重聽 ~03:15–04:15*

⚠️ **這條規則是整個新 prompt 最重要的保險絲**。寧可多標一個 `[？]`,
也不要讓「confident 錯誤」混進知識庫。

### 真實停頓 → `……`

**不要**對真實停頓用標記。講話卡住、情緒來了、話題跳、沉默空檔,都用 `……`:

> 所以鋼琴對我講好像不是展現的意思,它就是一個工具……。

### ⚪ Meta-note `[註：...]` — 只讀不寫

如果讀到既有校對稿裡有 `[註：某某說明]`,那是使用者回頭自己補的**旁註 /
澄清 / 延伸思考**,不是原始話語。**Claude 碰到這種標記一律原樣保留,
不要修改、不要刪除、也不要自己新增**。

用途舉例:
> 它有一個[註：情緒]氣候模型
> 因為它裡面很多代稱[註：心理學詞彙、或作者造的新詞]、很多很多名詞

這條是保險絲:meta-note 跟原話混淆會污染長期知識庫/RAG 檢索,
所以寫和讀要嚴格分開 — 使用者寫、Claude 只讀。

## 輸出格式

**只輸出一個檔案**:`_proofread/<檔名>.md`

**標點一律全形中文**。逗號用 ，、句號用 。、冒號用 ：、分號用 ；、問號用 ？、驚嘆號用 ！、括號用 （） 或「」;`<sup>字？</sup>` 和 `[？]` 標記裡的問號也是全形 ？。停頓用全形省略號 ……,不寫半形 ...(三個半形句點)。

**產出後自查**:校對稿不應出現以下任何半形 code point —— U+002C、U+002E、U+003A、U+003B、U+003F、U+0021、U+0028、U+0029;出現次數應全為 0(唯一例外:`...` 在 Markdown 語法或 URL 內允許,本專案輸出不會用到)。

- 校對後的全文(best-guess 填好、低信心 `<sup>字？</sup>`、停頓 `……`)
- 不要任何前言或後記
- 如果有 `[？]` 嚴重分歧 / 未知專有名詞,在文末加一條 horizontal rule
  `---`,之後用斜體寫 1–2 行簡短說明
- **不要產出 `_questions.md` 檔**
- **不要在校對稿裡寫時間戳**(時間戳留在 sidecar `.timed.txt` 工具檔)
