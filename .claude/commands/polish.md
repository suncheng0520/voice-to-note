# Polish 一份 proofread 稿

## 輸入 / 輸出

- **輸入**:`_proofread/<檔名>.md`
- **輸出**:`_polished/<檔名>.md`(同檔名,另一個資料夾)

若 `$ARGUMENTS` 為空:
- **同一個 session 已經在處理某個檔案**(剛 recheck 完、或剛校對完它)→ 直接用它,說一聲「polish 的是 XXX」即可,不用停下來等確認
- **冷啟動、或 `_proofread/` 裡有多個近期改動的候選** → 抓最新修改的 `.md`,先問「要 polish 的是 XXX,對嗎?」等確認

若 `$ARGUMENTS` 是檔名(不含 `.md`),直接開 `_proofread/<檔名>.md`。

## 目的與核心原則

Polish 稿的目的是**同一份內容的可讀版本**——給未來的自己重讀、給 RAG 檢索、給朋友看——不是潤稿,不是摘要,不是改寫。

**最高準則**:讀完 polish 稿跟讀完 proofread 稿,應該得到**完全一樣的內容、完全一樣的思緒順序、完全一樣的情緒起伏**,只是讀起來比較省力。

如果你在 polish 時發現自己在「想怎麼講比較通順」,停下來——那是潤稿,不是 polish。

## 操作規則

### ✅ 可以做

1. **破碎音節式 stutter 連續重複 3 次以上 → 縮成 1 次**
   - 「我、我、我發現」→「我發現」
   - 「就就就變成」→「就變成」
2. **同字/同詞連續重複 2 次但明顯是 stutter → 縮成 1 次**
   - 「去、去運動」→「去運動」
   - 「那個、那個模型」→「那個模型」
3. **重複但明顯是強調/排比 → 保留,不論幾次**
   - 「不是、不是」「就是、就是」「沒有、沒有」(並列、有節奏)
   - 「一直推、一直推、一直推」(完整詞組的節奏性重複,情緒承載)
   - 「各式各樣的不安、各式各樣的焦慮、各式各樣的心理活動」(刻意排比)
   - 判斷基準:講到一半卡住重來的是 stutter;**完整詞組刻意重複的是節奏**,
     縮了會違反最高準則的「完全一樣的情緒起伏」
4. **單獨孤立的 呃 / 哎 / 誒 / 啊 → 刪除**;但下列情況**保留**:
   - 引語標記:「他說誒」「捕捉到說哎」(在引別人講話,不是你在 hesitate)
   - 感嘆起句:「哇,今天怎麼這麼好看」「啊……就我內心」
   - 語氣助詞黏在詞後:「這樣啊」「困難啊」(拿掉會怪)
5. **明顯的同義疊詞去冗**
   - 「一樣同樣的」→「同樣的」
   - 「表面表面功夫」→「表面功夫」
   - 「有一個、有一個」→「有一個」
6. **校對稿裡的(括號)meta-note → 統一成 `[註:...]` 格式**
   - 「它有一個(情緒)氣候模型」→「它有一個[註:情緒]氣候模型」
7. **標點一律全形中文**(，。：；？！（） 或「」)——跟 `prompts/proofread.md` 同規格

### ✅ 必須保留原樣

- 所有 `……`(真實停頓,是節奏的一部分)
- 「嗯」「就是」「我覺得」「然後」(語氣/思緒,不是填充)
- `[註:...]` 原樣
- `<sup>字？</sup>` 原樣(問號是全形)
- 段落結構(不合併、不拆分、不重排)
- 「」引號、括號類標記

### ❌ 不可以做

1. **不合併兩個獨立想法**,即使在講同一件事
2. **不加原本沒有的連接詞**(因為 / 所以 / 於是 / 但是)
3. **不改語序、不調段落、不加小標、不做摘要**
4. **不修正語意錯字**——**例外**:校對稿有**明顯語意翻轉**的漏字(整句自相矛盾、讀起來語意相反),polish 可以主動補上,並用 **粗體** 標記被補的字,讓人一眼看得出改動。例:「不過閱讀日是我想要講的內容」⇒「不過閱讀日**不**是我想要講的內容」
5. **不把校對稿文末的 transcription-meta 說明帶進來**(polish 稿要讀得乾淨;那行說明屬於校對階段)。
   文末的 `【recheck flag】` 段同理——**絕不帶進 polish 稿**,而且看到它還在就代表
   使用者可能還沒處理完,先提醒她刪掉(或確認處理完了)再繼續 polish

## 產出格式

- **不要檔頭**(不加 HTML 註解、不加 title——使用者會砍掉,直接正文開始)
- 依照上述規則 polish 過的內容
- 段落間用**一個空行**分隔(跟 proofread 同)
- 不要前言、不要後記、不要小標

## 自我檢查(寫完後必做)

1. **全形標點檢查**:`grep -n '[,:?!;()]' _polished/<檔名>.md` 應該**零命中**(全檔沒有半形標點)
2. **段落數對齊**:polish 稿的段落數應該跟 proofread **完全一致**(段落沒合併、沒拆分)
3. **抽三段比對**:隨機挑 3 個段落,讀 proofread 版和 polish 版,確認:
   - 沒多加東西
   - 沒減少 idea
   - 順序一樣
   - 情緒/語氣一樣

## 結尾回報

寫完後告訴使用者:
- 「Polish 完了,在 `_polished/<檔名>.md`」
- 如果做了漏字補字(規則 ❌4 例外),**明確列出哪些地方補了什麼**
- 不要自誇「讀起來更流暢了」之類——結果讓使用者自己判斷
